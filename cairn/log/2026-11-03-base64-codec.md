# SCRAM base64 runs on base64-codec

The base64 crate gave way to base64-codec 0.1, as the family decided on 2026-11-03. src/rfc5802.rs encodes `c=` and `p=` and decodes `s=` and `v=` through two private helpers over `Base64Codec::default()`. The codec never fails, so the decoder refuses a value it did not read clean, which keeps `SaslScramError::InvalidBase64` for a byte outside the alphabet or data after the padding; a missing padding is now accepted, which costs nothing since a signature still has to match byte for byte. No public type changes, so the release can stay 0.1.x; the minimum Rust version rises to 1.89 with the codec.

The fuzz oracle in fuzz/fuzz_targets/scram.rs keeps the base64 crate on purpose: it recomputes the signature from primitives independent of the crate under test. Its strict decoding only means a salt the mechanism reads leniently never reaches the verified path there, never a false alarm.

Capabilities moved: packaging, scram.

Verified: `cargo clippy --all-targets --all-features` clean, `cargo test --all-features` passed (80 unit tests, `an_unpadded_server_signature_verifies` new), `cargo check --no-default-features` and `--no-default-features --features scram` clean.
